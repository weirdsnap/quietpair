# 建议身份模型：从行号锚到内容锚

状态：**已定案，待实施**（2026-11-11 逐条讨论定案，决策过程见 `research/DISCUSSIONS.md`，本地未提交）
关联：取代排期中的 ③b（行号映射，已明确跳过）；三期与 ③c（LSP 定点查询）合并

## 背景：行号锚为什么立不住

建议从出生就锚在 `(file, line)` 上，这个锚天然会漂，且有四类失效场景：

1. **同文件插行/删行**：问题上方插了几行，±3 窗口对不上 → 假「修好了」（原 ③b 只治这一类，被判定为战术补丁而跳过）
2. **编辑落在问题区域内**：真正的修复恰恰大多发生在区域内，位置比对在这里必然失效
3. **语义等价修复**：代码重写一遍，行号文本全变，bug 其实没了——任何位置比对都认不出
4. **跨文件修复**：「调用与声明不匹配」的证据在调用处，修复落在声明处（③a 已用 importGraph 圈定候选，但只是圈定不是确认）

核心洞察（用户提出）：**问题的身份是论断不是坐标**。坐标是载体的偶然属性，内容才是身份本身。

## 决策定案（D1–D6）

### D1 锚点单元：原文片段锚（A）

建议携带问题代码的**原文引用**（quote，2~8 行），身份 = 文件 + 片段内容。行号降级为纯展示用途。

- 选中理由：零工具依赖，任何语言任何项目可用；守望分析本来就是 LLM 看着代码出的，引用原文成本低
- 被否：B LSP 符号锚（语言服务器不总在、守望链路不走 LSP、粒度过粗——一个函数里多条建议区分不开）留作三期增强；C 混合一期成本过大
- 白送的红利：**文件内移动免费**——片段文本不变，全文搜索在新位置直接找到，锚自动存活、行号顺带更新

### D2 锚的获取：混合（LLM quote 为主 + 行号截取兜底），锚分强弱

- **强锚** = LLM 在建议 JSON 里输出 `quote` 字段（照抄原文），且通过校验（见 D3 双档匹配，在被分析内容里能找到）
- 校验失败（模型转述、改写）→ **降级为无锚**，行为保持现状，不丢弃建议（内容仍有价值，只是身份弱）
- **弱锚** = 有行号时按行号截取 ±N 行（用户拍板保留的兜底，覆盖 LLM 不给 quote 的场景）
- **安全硬规则**：弱锚永远没有确定性裁决权。行号本身常偏，弱锚可能从出生就钉错位置——它只能作为线索进 LLM 复审，并在 prompt 中注明「此锚来自行号截取，位置可能不准」。错误的锚比没有锚危害大：没有锚走诚实的不确定三态，错误的锚会给出斩钉截铁的错误判决
- prompt 对 quote 的规矩：必须是**问题证据**所在的最小连续片段（如「调用处那几行」），足以唯一定位——「片段还在 = 问题可能还在」的推断只在片段选得准时成立

### D3 匹配语义：双档精确匹配，找不到一律复审

确定性层只做两种匹配，同一套代码同一份测试：

1. **精确匹配**（逐字节）
2. **缩进归一化匹配**（逐行去首尾空白；模型最常见的偏差是重排缩进），匹配方式记埋点

- **多处出现**：全部位置记录，确认时任一位置存活 = 锚存活；全部消失 = 进复审
- **找不到 ≠ 修好了**：找不到只说明「文本变了」= 修了或重写了，字符串匹配分不开，一律 LLM 复审，携带三样证据：原始 quote、问题论断（title/detail）、变更集线索（diffVsLastAnalysis 变更区域 + 相关文件动向）
- **模糊匹配只当证人不当法官**：未来若「重写」类复审量大，可加相似度候选附进复审 prompt 帮定位，但裁决永远留给 LLM。相似度阈值是拍脑袋数，判错说不清——违反「确定性分支不说过头话」

### D4 confirmFix 判定树：强锚可获得确定性 rejected

```
① 全工作区没动过（editTracker）
   → unchanged：「你还没改代码」——确定性，锚无关，保持现状
② 强锚 + 片段在当前内容里找到（双档）
   ├─ 相关文件（importGraph）也没动过
   │   → 确定性「没修到点上」：证据原样还在，相关文件都没碰
   │   → 措辞保留「几乎可以肯定」：importGraph 是一级启发式，
   │     远程修复（全局配置/动态分发）圈不进来；埋点盯误报率
   └─ 相关文件动过 → LLM 复审（可能跨文件修复）
③ 强锚 + 片段找不到 → LLM 复审（带 D3 三样证据）
④ 弱锚 → 找到/找不到都进复审（D2 安全规则）
⑤ 无锚 → 现状行为（review；① 仍兜底）
```

- ② 取代了 ③a 的 `untouched` 分支（±3 区域 diff 检查 → 锚存在性检查），插行漂移问题随之消失
- ② 的确定性 rejected 省掉最常见场景的一次 LLM 调用：用户改了无关代码、问题原封不动
- 被否：「除 ① 外全部复审」——更保守但每次确认花 token、等待久，常见场景不值

### D5 身份键：文件 + 锚哈希 + 归一化 title

- **身份键 = 文件 + 锚哈希 + 归一化 title**；锚哈希取缩进归一化后的 quote 内容（与匹配同一份归一化）
- 带 title 的原因：同一片代码可能挂两条不同建议（同几行既有 bug 又有风格问题），只靠锚哈希会撞车
- title 归一化（trim/大小写折叠）只能减少不能消除跨轮措辞漂移——重分析换个说法，生命周期会记成「旧消失 + 新出现」。已知噪声，接受并埋点观察；兜底手段是以后给 prompt 加「复用既有标题」规矩
- 无锚回退 `file + 归一化title`（现状语义的收紧版）
- `markViewed`（「← 用户正在看这条」）同步换身份键匹配——顺带修掉「无行号时 undefined === undefined 直接相等」的旧洞

### D6 分期：三期走，每期独立成立

| 期 | 范围 | 验收 |
| --- | --- | --- |
| 一期（0.1） | `Suggestion.quote` 字段 + 分析 prompt 改造 + 双档校验/降级 + 强弱锚分级；confirmFix 走 D4 判定树 | 假「修好了」/假「没修」主体消失；quote 校验失败率、rejected 误报率进埋点 |
| 二期 | SharedContext 身份键换锚 + markViewed 换锚 + 建议生命周期（persists/new/fixed 追踪） | 同一条建议跨轮身份稳定；20 格栈不再被重复条目挤爆 |
| 三期 | LSP 符号锚（合并原 ③c）：符号路径给片段搜索圈范围、给无锚建议补身份；语言服务器不在时全降级 | 符号锚在场时无锚建议占比显著下降 |

铁律：下一期缺席不影响上一期独立成立。

## 已有工作对照（2026-11-12 调研，原始链接见 research/anchoring/PRIOR_ART.md，本地未提交）

**不谋而合（方案被外部佐证）**：

- **内容即身份**是工业界独立收敛的答案：SonarQube（行内容哈希 + 块移动检测）、Semgrep（`match_based_id` 刻意不含行号）、Meta Infer（位置无关 bug hash）、CodeQL（稳定实体名）——行号锚在 issue identity 场景被一致抛弃，我们是第五个独立收敛
- **确定性修复确认是主流**：reviewdog（重跑全量、差集自动 resolve/delete）、SonarQube（哈希不上 = Fixed）；严肃静态分析工具无人用 LLM 判修复——LLM 重审的是 CodeRabbit 这类 AI 评审机器人，恰是它们最弱的环节
- **LLM 照抄原文可靠**：Claude Code 精确 `old_string` + 唯一性校验、Aider SEARCH/REPLACE 块，与 quote anchor 同构
- **缩进归一化是标准操作**：`git diff --color-moved` 的空白容忍档同思路
- **强弱分级降级有先例**：SonarQube 的次级匹配（rule+行号+message 兜底）、Hypothesis 的 fuzzy fallback

**差异点（无人占位，本方案的原创性主张）**：

1. **拒绝相似度模糊匹配**：Hypothes.is 的 fuzzy anchoring 在原文被编辑后静默锚到别处相似文本（hypothesis/client#7571；实证 27% 注释成孤儿、仅 3.5% 可恢复）——我们的保守路线有公开事故作证
2. **确定性 rejected 作为一等状态**：现有系统失配后的归宿只有孤儿（Hypothesis）/ outdated 标记（GitHub）/ 静默新建（Coverity），没有带确定语义的状态转移
3. **场景空档**：所有先例跑在 CI/PR（有 diff 基线）；编辑器内、无 commit 边界的实时内容锚无人做（Zed #59157 提了需求未实现）

**从调研中吸收的资产**：

- Google Critique 用新旧两版 diff 对齐评论位置——我们的 analyzer 本来就存分析时刻快照（`lastContent`），**diff 对齐这条路对我们开放**，复审时可作内容搜索的补充证据（三期评估）
- 多处出现的消歧若不够，可参考 Hypothesis 的 prefix/suffix 上下文或 Claude Code 的唯一性校验（现定案：全部位置记录、任一存活即存活）

## 测试策略（对齐 tests/README.md 四层）

- **L0 纯函数**：双档匹配（精确/归一化/多处出现/全消失）、锚哈希稳定性、身份键生成（含撞车场景：同锚不同 title）、D4 判定树的判定表全组合（锚强度 × 找到与否 × 工作区动向 × 相关文件动向）
- **L0 属性测试（fast-check）**：归一化幂等；锚找到 ⇒ 内容包含锚；行号更新后锚仍在该位置
- **L2 契约**：分析 prompt 含 quote 字段要求与「照抄原文」规矩；Suggestion schema 含 quote/anchorStrength
- 埋点断言：校验失败降级、弱锚进复审的 prompt 标注、确定性 rejected 的措辞 hedge 都可在 stubbed 层断言

## 风险与埋点指标

| 风险 | 缓解 | 指标 |
| --- | --- | --- |
| LLM 不照抄原文，quote 校验失败率高 | 降级不丢弃；prompt 给正反例 | quote 校验失败率、归一化回退占比 |
| 弱锚钉错位置 | 无确定性裁决权，仅作线索 | 弱锚建议的复审结论分布 |
| 确定性 rejected 误报（远程修复圈不进） | hedged 措辞；importGraph 持续改进 | rejected 后用户仍点「已修好」的翻案率 |
| title 措辞漂移污染生命周期 | 归一化 + 接受噪声 | persist 被计为 new 的比例 |

## 明确不做

- ③b mapOldLineToNew（行号映射）：内容锚的文件内移动红利使其失去意义，已跳过
- 模糊相似度裁决：只当证人不当法官
- 模型微调：所有改进走外部手段（prompt、门控、埋点），长期依赖模型厂商演进
